## Sandbox and proxy
- **Sandbox provisioning:** `Infra.Integration.SandboxApp.CreateAsync()` POSTs `https://sandbox.realtime.ably-nonprod.net/apps` (or the host `ABLY_ENDPOINT` resolves to, through `Defaults.GetPrimaryDomain`) with the embedded `test-app-setup.json` once, with no retry, a 30 s timeout and the status checked before parsing; `DeleteAsync()` sends `DELETE /apps/{id}` with Basic auth, best-effort. Per-run provisioning maps to an xunit collection fixture: every UTS integration class joins `[Collection("UTS Sandbox")]` with `ICollectionFixture<SandboxAppFixture>`, so one app per run, deleted in the fixture's `DisposeAsync`, and the integration classes run serially. **Client targeting:** `Endpoint = TestEnvironmentSettings`-style `ABLY_ENDPOINT` or `"nonprod:sandbox"`, `Key = app.Keys[0]` (Basic auth over TLS). Waits are wall-clock: state waits 15 s default, `PollUntil` needs an explicit 10–30 s timeout. Teardown closes every client the base built (await CLOSED only from states that can reach it).
- **Proxy:** version pinned to uts-proxy **v0.3.0** (the version `proxy.md` documents). Binaries per OS (verified 2026-10-16, `gh api repos/ably/uts-proxy/releases/tags/v0.3.0`, STOP-6 decision log #13): `uts-proxy_0.3.0_{darwin,linux}_{amd64,arm64}.tar.gz` only — **no Windows asset**. Pinned SHA-256: darwin_amd64 1355526543c3022f87efb7f564f55200b78edc68d84c7dba2e49f63429e3b788; darwin_arm64 a948f99b7daf9b3bffff742f6405637d40a79947389309eed5f87e59026de9a5; linux_amd64 de741ba21f3630fea4f59714d00585638d565005599ecd84179931eba248f280; linux_arm64 15b5ca87c40c2c4ff350c94af1911cea0ad6be5a2d890ba41029bc4b8bc52c61. Extraction with the system `tar` (System.Formats.Tar isn't available on net462/net6). Plan: `ProxyManager` downloads the asset for the OS/arch into `~/.cache/uts-proxy/v0.3.0/` (the same layout as the existing cache), verifies a pinned SHA-256, serialises the download with a lock file, starts it on a fixed control port (one process: proxy classes share `[Collection("UTS Proxy")]`), waits for `GET /health`, and kills it on process exit. Local override `UTS_PROXY_LOCAL_PATH` (a configuration override, not a gate). Platforms without a release binary (Windows, confirmed): the proxy tier needs `UTS_PROXY_LOCAL_PATH` (build from source) and **fails** with a message naming it rather than skipping; CI runs the proxy tier on Linux only. `ProxySession` (`create_proxy_session(endpoint:, rules:)` defaulting the endpoint to the sandbox; the control API takes `target{realtimeHost, restHost}`, so the endpoint is resolved client-side), `AddRules(rules, position)`, `TriggerAction`, `GetLog()` → typed `ProxyEvent`s, `CloseAsync()`; rule builders (`ProxyRules.WsFrameToClient(action: 11, …)`) stringify `match.action`. Clients point at `Endpoint = "localhost"`, `Port = session.ProxyPort`, `Tls = false`, `AutoConnect = false`. **Auth through the proxy (D-18, proposed):** `AuthCallback` returning a `TokenDetails` obtained by a separate client that talks straight to the sandbox with the app key — Basic auth over the plain hop is refused by the SDK (RSC18, AblyAuth.cs:535-541), and the token client must not add requests to the proxy log. Commented in the proxy base.
